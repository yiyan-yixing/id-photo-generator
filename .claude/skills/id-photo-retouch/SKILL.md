# 证件照精修

把手机照片做成标准证件照：抠图换底色、裁切构图、磨皮美白。

## 判断"做好了"的标准

用户的原话是最好的验收标准：**"轮廓边缘结合自然，不能看出来抠图的效果"**。

自动生成的人像处理，几乎所有的"假"都出在**边缘**和**肤色**上。密集的头发、面部、衣服
通常都没问题 —— 实测：密集头发与同分辨率原图的逐像素差约 10，面部 14，衣服 17，
而**发际边缘差 60**。差异集中在边缘，就往边缘查，别去改脸。

## 量化验收方法（关键中的关键）

肉眼看"头发发灰"极易误判。**我在这上面错过两次，派出去的独立评估 agent 也踩了同一个坑。**

**必须先统一取景和分辨率再比。** 成品是**裁切图**，拿整张原图缩到 480×640 去比，
两边根本不是同一取景 —— 会得出"头发被提亮 40 级"、"皮肤质感损失 80%"这种假结论。
（后者是独立评估 agent 报的"最严重缺陷"，用正确方法复测只有 59–84% 保留，不成立。）

正确做法：

```python
crop   = 用成品同一裁切框裁原图
ref    = cv2.resize(crop, (480, 640), interpolation=cv2.INTER_AREA)   # 原图同法降采样
out    = np.array(Image.open('成品.jpg'))
d      = np.abs(out.astype(int) - ref.astype(int)).max(axis=2)
# 分区域看 d 的均值，而不是看整图
```

实测基准（这张参考照片）：密集头发差 ~10、面部 ~14、衣服 ~17，而**发际边缘差 60**。
差异集中在边缘就查边缘，不要跑去改脸。

**验证过的其他陷阱**：
- `alpha < 1` 处底色会透出来 —— 要直接确认密集头发的 `alpha` 是否 ≈1，别凭肉眼
- 肤色别只看亮度，要看 **`b*`**（色度才是"发灰"的判据）
- 用**局部 7×7 标准差**或 `|gray − gaussian(gray,2.5)|` 量皮肤质感，而不是看整体观感

### 派评估 agent 时必须先问它「你能看到图吗」

实测：子 agent 的 `Read` 经常返回 `[Unsupported Image]` —— **它看不到图，却照样能写出一份语气笃定的视觉评估**。
两轮实测对比：

| | 第一轮（没说） | 第二轮（明确要求先声明） |
|---|---|---|
| 是否承认看不到图 | ❌ 不承认，直接写视觉结论 | ✅ 开头就声明"不做视觉判断、不编造" |
| 结论可信度 | 6 条里 4 条错 | 视觉结论为空，测量可信 |

**看不到图的评估者会犯的两类错**（都是真实发生的）：
1. 把「暗的底部」判成"背景没换" —— 实际那是**人物的校服填满了底部**。它不知道图里有什么，只能假设边缘应当是背景。
2. 用"暗行剖面"找下巴，找到的是**下巴下方的阴影**，于是把头部占比算成 52%（实际 64%）。

**所以**：给它材料时同时提供「同裁切同降采样的参考图」并写明裁切框；
要求它**逐条标注哪些结论来自测量、哪些来自目视**；
它若声称看到了图，先让它描述一个只有看图才知道的细节（例如"左下角是什么"）来验证。

## 专业修图师的实际做法

调研了中英文的实操资料（来源见文末）。最有价值的一条：

> **图层蒙版不是问题所在。** 发白源于**边缘像素的颜色数据**本身已经烘焙了旧背景色。
> 蒙版只控制 alpha，管不了颜色。

专业公式 `C' = C − (1−α)·B0 + (1−α)·B1` —— 与本项目"反解 + 重合成"的代数等价。
方向是对的。

**完整流程（顺序有讲究）**：整体校正 → 液化（结构，必须最先，否则后面的修饰会被拉花）
→ 去瑕（**在磨皮前**，要从干净的原像素克隆）→ 磨皮 + 中性灰/双曲线（**保留毛孔，只处理
低频**）→ 统一发色 → 抠图换底 → **去边（必须对着最终底色做）** → 调色 → 锐化（最后）。

**去边 / 消除发白的专业手法**：

| 手法 | 自动化等价 |
|---|---|
| Select and Mask 的 Decontaminate Colors | 反解公式（已实现） |
| **最小值滤镜 / Shift Edge 负值**（收缩 1px 干掉残留白边） | `cv2.erode`（**已实现，contract=1**，残留亮点 180→36） |
| **Darken 模式去边**：在边缘带取 `min(像素, 发色参考)` | 反解上限（已实现） |
| Remove White Matte / Defringe | 边缘像素向内侧取色 |
| Lighten 模式保留飞发 | `np.maximum` |
| 通道抠图（浅色/飞发，Select and Mask 失效时） | 取对比最强的通道 → 拉伸→ Otsu |

**注意收缩的度**：实测 contract=1 残留亮点从 180 降到 36（5 倍），但 contract=3 开始
吃掉细发丝 —— 专业上叫"头盔发"（helmet hair），是明确的失败特征。

### 「外扩找回飞发」与「灰色软带」是一对矛盾

外扩搜索范围能找回飞发（见后文），但它同时让蒙版在**更宽的一条带**上停在中间 alpha，
而中间 alpha 叠在饱和底色上**就是那圈灰白薄雾** —— 用户会描述成"边缘有阴影"。

两个参数必须**一起调**，只调一个会按下葫芦浮起瓢：

| 配置 | 中间 alpha 像素 | 软带比底色暗 |
|---|---|---|
| expand=30 / narrow=0.30（只外扩） | 4428 | 15 级 |
| expand=30 / narrow=2.5 | 2871 | **7.5 级** |

`narrow` 是对过渡带做对比度拉伸（把 alpha 推向 0/1）。**在外扩之前调它几乎没用**，
因为那时过渡带本来就窄；外扩之后它才是决定性的一步。最终定 `expand=15 / narrow=2.5 /
narrow_radius=4 / post_blur=0`。

**排查顺序**：先确认是不是软带（量"过渡带像素相对底色的亮度差"），再动 `narrow`；
不要一上来就调 `contract`（收缩）—— 收缩是治**残留色边**的，治不了软带。

**"自然"的量化标准**（专业资料给的数）：磨皮强度 <30%；保留鼻梁/颧骨的锐度；
用 HSL 的橙/红亮度调肤色而不是整体提亮；质感掉到 **50–70% 就该停**。

## 自检的两道闸门与校准

`pipeline.py` 每次出图会跑：

| 检查 | 指标 | 阈值 | 实测校准 |
|---|---|---|---|
| 肤色自然度 | 皮肤 `b*` | ≥12 | 默认 14.0；美白开到 40 时 6.8（触发） |
| 质感保留 | 高频能量比 | ≥0.55 | 默认 66%；只磨皮 80%；重磨+满去斑 46%（触发） |

阈值都是**实测校准**出来的，不是拍脑袋。而且要知道它们的**边界**：
- 质感检查抓不到"几何变形"，肤色检查抓不到"磨皮过头"
- 反解上限（cap）的包络是**局部均值**，在脸颊边缘会被旁边的深色头发拉低。
  实测 cap 从 1.25 收到 1.0 时，脸部自己的 `b*` 会掉到 10.1（发灰）、质感掉到 38%
  —— **为了 7% 的轮廓改善削到人脸，不划算**。调这个参数必须同时看肤色和轮廓两项。

## 发丝级：分块推理（tiled inference）

模型固定 1024 输入是**细节的天花板** —— 1200 万像素的照片被压到长边 1024，
几个像素宽的细发直接消失，蒙版再好也解不出来。表现就是**发际线光滑得像戴假发套**。

**解法：切成带重叠的小块，每块各自跑满 1024，再羽化融合。** 等价于把抠图分辨率
提高到 2–3 倍。

实测（同一张照片，头顶发际）：

| tiles | 推理耗时 | 效果 |
|---|---|---|
| 1 | 1.2s | 边缘是光滑曲线，飞发全无 |
| **2** | **3.6s** | **一缕缕飞发清晰可见** ← 默认 |
| 3 | 7.7s | 再多一点，不划算 |

视觉模型对照：1x "像戴了假发套"，2x "出现大量单根发丝，真实感质的飞跃"。

**但加块数不是越多越好 —— 3x3 反而更差。** 每块里的主体占比变小，偏离了模型训练时的
分布，发际线出来发灰发糊，像底色渗入。**实测 2x2 是这套模型的甜点，再多要靠更强的模型，
不是靠更多块。**

另一个教训：**我的数值指标测不出这个退化**（发了 4 个指标，1/2/3/4 块都无趋势），
是视觉模型对照发现的。**边缘质量的评估，数值指标不可靠，必须看图。**

**实现要点**：
- 每块向有邻居的方向**外扩 overlap**（0.25），相邻窗口共享一条带
- 融合用**羽化权重**：每块只信任自己的内部，边缘渐变到 0 —— 这正是需要重叠的原因
- 总耗时 = 块数 × 1 秒左右，端到端从 5.8s 增到 8.5s

## 抠图必须用模型，启发式修不了内部误判

**这是整件事最大的教训，我用十几轮试错才认清。**

我最初的做法是「Vision 语义分割 → 用两色关系 `a=(C−B)/(F−B)` 做启发式修边」。
这在**轮廓边界**有效，但它是个**局部分类器**，且在实心区被我**主动锁定**（实测解除会毁图）。
后果：当 Vision 把一块**背景误判进轮廓内部**时，下游**没有任何环节能纠正它**。

实测那张参考照片：**轮廓内部（距边界>20px）有 85,442 像素是背景，最大一块 28,896 px**。
它在成品上表现为头发中间一块灰白斑。我试了收缩/外扩/收窄/cap/涂色/gamma/闭运算等十几种
参数调整，**全部无效** —— 因为病灶在分割，不在边缘。

**正确做法：用学习型抠图模型。** 换 RMBG-1.4（ONNX，168MB）后：
- 内部假前景**直接消失**（模型是在学"什么是前景"，不是在做局部颜色判断）
- 推理约 1 秒（1024×1024）
- 视觉模型对照评估从「**不能交付**」变为「**基本可以交付**」

**模型下载**：HuggingFace 直连不通，但 **hf-mirror.com 通**，实测可下载（HTTP 206）。
GitHub release 资源不通（000），别走那条路。

**还要做一步导向细化**：模型固定 1024 输入，放大到 3024 后边界偏软。
用导向滤波（以图像为引导）把真实边缘结构传回蒙版，再做轻微对比度拉伸。
视觉模型判定这一步"边缘更锐利、光晕被抑制、发丝保留更多"。
注意这个细化**不假设前后景颜色**，所以不会重新引入内部误判。

## 核心算法：从图像反推 alpha（启发式，已被模型取代）

Vision 的前景蒙版是**粗蒙版** —— 它在发丝处是一条平滑斜坡，而原图那里是逐像素在
黑发和亮墙间交替。直接用会在纯色底上糊出一圈灰雾。

**反直觉之处**：直觉是"蒙版不平滑，把它磨平滑"。实测这反而更糟 —— 缺的是**细节**
不是噪声：

| 蒙版 | 与真实发丝的对齐度 r |
|---|---|
| 原始 Vision | 0.508 |
| 导向滤波磨平滑 | **0.338** ← 更差 |
| 图像反推 | **0.730** |

用 matting 的基本关系，F 为发色、B 为背景色：

```
a = (C - B) / (F - B)
```

### 三个必须处理的坑

**① 循环依赖。** 用 `alpha` 加权估计 F（`normconv(gray, alpha)`）会闭环：蒙版自身的
错误喂进 F 的估计 → F 被拉近背景色 → 局部对比度不足 → 判定不可用 → 退回那个错的蒙版值。

解法：**只用蒙版确信的区域估 F 和 B**（`alpha<0.05` 估背景、`>0.95` 估前景），
再用改进后的 alpha 迭代一两轮。

**② 两色模型在逆光发丝上失效。** 逆光的飞发本身是亮的，会被 `(C-B)/(F-B)` 误判成背景，
反解时被放大成**白条纹**。所以：只在粗蒙版的过渡带内采用反推值，**实心区锁定原始蒙版**。
试过去掉这个锁定，杂散亮点少 5 倍，但发丝上出现明显白条纹，得不偿失。

**③ 反解会放大误差。** `F = (C - B(1-a)) / a` 在 a 小时极不稳定，最后几个百分点的
亮墙像素会被放大成近白，勾出整条轮廓的浅色边 —— 正是要避免的抠图感。
所以要**给反解出的 F 加上限**：不超过局部发色包络的 1.25 倍（相对值，允许真正较浅的头发）。

### 边缘那圈亮环：先推公式，别再调参数

**我在这上面反复改了五六轮都没修掉，根因是没先做数学推导就去试参数。**

设真实覆盖率 `a_true`、估计 `a_est`，令 `k = a_true/a_est`，则合成的误差是：

```
误差 = a_true · (1−k)/k ·(原背景 − 新底色)
```

新底色比原背景暗时（白墙 → 蓝底），**只要 alpha 被高估（k<1），误差就为正 ——
边缘比应有的亮**，勾出整圈亮环。

**关键推论：这个误差源于 alpha 的估计误差本身，调蒙版参数只能减小它、消不掉它。**
所以 `narrow`、`expand`、`contract` 全都在治标 —— 我前面几轮就是这么绕进去的。

**正确做法：过渡带里根本不要反解颜色，直接涂头发的本色。** 头发接近单一色调，
从内部（`alpha>0.97`）取局部发色（LAB 三通道各自归一化卷积），把 `alpha<0.95` 的区域
整片替换掉。这就是修图师"从头发内部克隆到边缘"的自动化等价，**一步消除**而非缩小。

实测：头顶亮环完全消失，四段发际（头顶/左上/左中/右下）全部干净。

**教训**：边缘出问题时，**先写出误差公式判断它是不是参数能治的**，
再决定调参数还是换做法。我在"调参数"上花了五轮，换做法一轮就解决了。

### 换底色不能带白边

修图是在白底合成图上做的。直接拿它换底色会引入误差：

```
误差 = a(1-a)(原背景 - 前景)
```

`a=0.5` 的深色头发上可达 **49 个灰阶**。做法是构造「修图后人像 RGB + 独立 alpha」，
混合权重取 `soft * alpha`（非皮肤处和半透明处自动归零）。实测皮肤区 `alpha` 最小值
就是 1.000，与过渡带零重叠，方案成立。

## 在放大后的画布上修，最后再缩回

**这是提升边缘精度最有效的一招。** `contract=1px`、`post_blur=1px`、收窄重映射这些
都是**像素单位**的操作；在 2300px 的裁切画布上做完再一步缩到 480px，它们等效不到
0.2 个输出像素，台阶就显出来了 —— 发丝呈**块状**。先把画布放大再处理，这些操作
变成亚像素，过渡自然；最后的降采样还会把反解留下的单像素色度噪声一并平均掉。

实测（同一张参考照片）：

| 超采样 | 峰值内存 | 耗时 | 发丝 |
|---|---|---|---|
| 1.0x | 1.47 GB | 3.7s | 块状 |
| **1.5x（默认）** | **2.72 GB** | **5.8s** | 细腻 |
| 2.0x | 4.47 GB | 8.7s | 最细腻 |

**内存按倍数的平方增长** —— 2x 时画布 4638×6184 是 2870 万像素，多个 float32
中间数组叠加就上到 4.5 GB，对后台服务太重。所以加了**画布像素上限**
（`max_work_pixels`，默认 1800 万）自动封顶：6000×8000 的裁切请求 2x 会被压回 1.0x。

**放大引入的两个坐标坑**（都真实踩到过，且都是**静默误报**，不会崩）：
1. 画布上的 `midline_c` 必须乘上倍数 —— 它来自原图关键点，却要和放大后的 `sub_w` 一起用
2. 自检里 `face_landmarks` 返回的是**放大后**坐标，必须先除回原图尺度再乘比例。
   漏掉除法会报出与倍数成正比的假偏移（1.5x → 22.9%，2.0x → 45.7%）

## 修图的尺度与边界

**修图必须在裁切尺度上做。** 导向滤波半径、眼下提亮的包络核都是**像素单位**，参数是在
裁切后（约 3000px）调好的。跑在全分辨率原图上，所有滤波的物理作用范围都变了，效果对不上。

**皮肤蒙版别吃进头发。** CIELAB 之前先看 YCbCr 的 Y：实测头发 Y 的 p90 = 86，
脸/脖子 Y 的 p10 = 93 —— 有干净分界。阈值 `Y>=60` 太松会吃进头发；`Y>=95` 会丢掉
阴影下的脖子（覆盖降到 84%）。另注意形态学闭运算（15×15）会把脸和旁边头发连成一片，
羽化的外溢也会扩大影响。

**暗部提亮不要打到头发。** 给衣服加的提亮（`amount*(1-L)^1.5`）会顺带提亮头发，
损失发丝对比度、看起来发灰。**限制在脖子以下**。实测：密集头发与同分辨率原图的差
从 16.8 降到 9.7，而衣服保持 16.6 的提亮。

同理，**全局 gamma 提亮对暗部抬升最猛**，会把头发洗灰。要么不用，要么幅度很小。

## 反解只在半透明处做，实心区不要碰

**「眼皮发绿」的真正原因，我找了很久。**

反解公式 `F=(C−B(1−a))/a` 除以 α，会**放大色度差**。它在 α 明显小于 1 的过渡带是对的，
但在**近似实心**处（α 接近 1）本来就不需要反解 —— 那里像素就是纯前景，减掉背景再除 α
纯粹是引入误差。

问题在于**蒙版在任何地方都不是完全可信的**：RMBG 在**眼睛附近**的 α 会低于 1，
于是上眼皮被反解"去暖"了。

**逐级追踪**（同一张照片，上眼皮的 G−R）：

| 阶段 | G−R |
|---|---|
| 裁切原图 | −23.6 |
| 全局提亮 | −24.0 |
| 修图后 | −21.4 |
| **反解后** | **−15.9** ← 一步偏了 5.5 |
| 涂发色后 | −15.9 |

其他每一步都在 2 以内，只有反解跳了 5.5。改成 **α>0.95 处跳过反解**后回到 −21.3，
视觉模型判定"灰绿已消除"。

**排查提示**：怀疑某处颜色不对时，**逐级打印该区域的色度**，看跳变发生在哪一步 ——
比盯着公式猜快得多。

## 美白：色度要「按比例降」，不能「减固定值」

**暗部发灰绿**是美白最常见的副作用，根因是减了个常量。

实测同一张照片：美白对**所有亮度**都减 a*−1.0、b*−2.0。

| 原图亮度 | 原 b* | 减固定值后 | 实际变化 |
|---|---|---|---|
| 150–185（亮） | 19.1 | 17.1 | **−11%** |
| 0–90（暗） | 5.8 | 3.9 | **−33%** ← 暗部黄度被削掉三分之一 |

暗部本来饱和度就低，同样减 2.0 相当于把它**去暖**了三分之一 —— 于是眼睑、眉间、发际
这些阴影区就发灰绿。用户会描述成"眼睛和眉毛之间、头发和前额有绿色阴影"。

**改成按比例缩放**（`a*×(1−0.08)`、`b*×(1−0.12)`）：

| 原图亮度 | 变化 |
|---|---|
| 150–185 | −2.8（美白保留） |
| 0–90 | **−1.1**（暗部几乎不动） |

视觉模型对照评估：灰绿阴影"基本消除"，肤色更均匀，**可交付**。

**排查提示**：怀疑"某处发绿"时，先按亮度分层量 a*/b* 的变化量，
看是不是"固定减法在暗部过度生效"，而不是去查颜色通道本身。

## 磨皮力度

默认 `smooth=0.35`。实测高频保留约 70%（66%→70%），视觉模型判定"比 0.45 更自然，
没有塑料感"。质感自检阈值 0.55 仍有余量（过度磨皮会掉到 46% 触发）。

## 美白：用 b* 守住"自然"

判据是 CIELAB 的 `b*`（黄度）：**正常皮肤 +12 ~ +25，低于 12 脸就往灰走而不是变白**。

| 设置 | L | b* | 判断 |
|---|---|---|---|
| 原图 | 144 | +16.0 | 基准 |
| 过强 | 152 | **+12.0** | 区间下沿，发灰 |
| 自然（推荐） | 148 | **+14.0** | 稳在区间内 |

`白=2.5 / 去红=0.8 / 去黄=1.5`。调到 7 就会掉出正常区间。

## 要能过自动核验

证件照要过学校/考试系统的人脸核验，**改的是明暗纹理，不能动五官几何**。验收方式：
用 Vision 对**成品图**重跑人脸检测，比对关键点与原图的位置，偏差应 ≤2px（实测 0.4px）。

**这道检查的边界要说清楚**：它防的是**几何变形**。磨皮磨得太狠、纹理全丢，关键点位置
不会变，这道抓不到。管"别过于白"的是 `b*` 那道。

## 坐标系：三个反复踩的坑

1. **EXIF**。Vision 读原始像素、不认 EXIF。必须先把旋转烘焙进像素再做任何事，否则
   分割、关键点、裁切全部错位。`cv2.imread` 更是完全忽略 EXIF。用 `ImageOps.exif_transpose`。
2. **蒙版必须与图像同朝向**。`segment` 不认 EXIF，对未归正的原图跑出来的蒙版是横的，
   和归正后的竖图对不上 —— 而且不报错，只会静默错位。让脚本自己在已归正的图上分割。
3. **正则在用 min/max 配对时要重新分组**。`facebox` 输出的是
   `(xmin, xmax, ymin, ymax)`，按 `(x0,y0,x1,y1)` 传进 `box_of` 会静默算歪眼区
   （实测两只眼睛 y 差出 270px）。坐标解析只保留**一份**，不要复制。

## 原图对比是必要的

出图后必须把原图一起给用户看 —— 否则无法判断换底后是否自然。界面上提供
「原图 | 成品」并排 + 全屏切换。

## 文件大小上限：花满预算换画质

报名系统常卡上传体积（常见「不超过 100KB」）。正确做法不是固定一个 JPEG 质量，
而是**在上限内取最高画质**：二分搜索质量（40–98）。

两个要点：
1. **色度抽样是最后手段**。降质量先，4:4:4 → 4:2:0 是最后的 —— 它糊的是彩色边缘，
   恰好是证件照最敏感的地方（发丝、底色交界）。
2. **上限是天花板不是目标**。给 100KB 额度就产出最好的 100KB 照片，
   这样各档体积才单调（不限 ≥ ≤200 ≥ ≤100 ≥ ≤50）。
   否则会出现「选了 ≤100KB 反而比不限更大」的反直觉结果 —— 我第一版就是这样。

实测：不限 63KB（质量 92）→ 提到质量 98 后 125KB；≤50KB 档实测 48.3KB。

## 输出规格与底色

| 规格 | 像素 | 打印尺寸 | 比例 |
|---|---|---|---|
| 学籍照 | 480×640 | — | 1.3333 |
| 一寸 | 295×413 | 25×35mm @300dpi | 1.4000 |
| 二寸 | 413×579 | 35×49mm @300dpi | 1.4019 |
| 护照/大二寸 | 390×567 | 33×48mm @300dpi | 1.4538 |

比例各不相同 —— 但头部占比和目标边距都是**比例**，所以各规格的纵向裁切相同、只差宽度，
且都居中于人脸中线。因此可以**在最宽的裁切上只修一次图**，其余规格横向切片复用。
`crop_w > 原图宽` 时用 alpha=0 补边，而非夹取，以保持比例严格正确。

构图：头部占画面高度 64%，头顶留白 9%，水平对齐人脸中线。
（实测成品头部占比 64.5%，与目标一致 —— 这条可以被自动验证。）

**底色规格不统一，这是实践中很常见的退件原因：**

| 用途 | RGB | Hex |
|---|---|---|
| 白底 | (255,255,255) | #FFFFFF |
| 蓝底（标准天蓝，多数影楼用） | (67,142,219) | #438EDB |
| **深蓝（考公，考试系统常用）** | (0,102,204) | **#0066CC** |
| 红底 | (255,0,0) | #FF0000 |

早期规定多数没写精确色值，**以受理机构的最新要求为准**。自动化管道应输出**精确的**
目标 RGB，而不是"看起来差不多的"蓝 —— 机器核验查的是数值不是观感。

## 判断"是否专业"的特征清单

按显眼程度排（来自专业资料 + 实测）：

1. **发际有旧背景色的残留边、或生硬的剪贴感** —— 最响的"业余信号"
2. **塑料皮肤** —— 没有毛孔、暗部被抹平
3. 面部平（缺少中性灰/双曲线的结构塑造）
4. **脸和脖子色调不匹配**（亮脸配灰脖子）
5. 眼神光缺失
6. 发色不均或有红调
7. 底色不是纯净单一色值
8. 构图错位、头部比例不对
9. 液化过头，不像本人
10. **"头盔发"** —— 飞发被清理得太干净，发际线像画上去的

## 去痣



默认**关闭**。痣属于身份特征，抹掉会降低与学籍档案、身份证的比对一致性。
需要时：DoG 找紧凑暗斑，再加一道**四向判别**（真痣四周各方向都是明亮皮肤，
而唇缘/鼻孔/发际线/耳朵这类边缘型误检至少有一个方向继续是暗的）—— 误检从 38 降到 4。
再用 `cv2.inpaint` 从周围皮肤填充，眉眼区设几何排除框兜底。

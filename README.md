# 证件照生成器

在手机上选一张照片，自动生成白底／蓝底／红底、四种标准规格的证件照。

照片**只在本机处理**，不上传任何服务器，也不联网下载模型（模型只需下一次性，之后离线可用）。

```
pipeline: EXIF 归正 → 抠图（学习型 matting）→ 人脸关键点 → 裁切构图
          → 放大处理 → 修图 → 反解前景色 → 合成底色 → 自检 → 输出
```

## 快速开始

```bash
pip install -r requirements.txt
./run.sh
```

首次运行会做两件事（约 1–2 分钟）：

1. 用 `swiftc` 编译两个 Vision 封装（`vendor/tools/*.swift`）
2. 下载抠图模型，约 1.1 GB

启动后终端会打印地址，手机连同一个 WiFi 打开即可：

```
手机浏览器打开:  http://192.168.1.17:8000
```

**存图**：点开大图后**长按 → 存储到照片**。页面上也有下载按钮，安卓和电脑可直接用；
iOS 上它会存到「文件」而非相册（`navigator.share` 需要 HTTPS，局域网明文 HTTP 下用不了）。

## 环境要求

- **macOS**（依赖系统自带的 Vision 框架做人脸关键点和兜底分割，**不能跨平台**）
- Python 3.11+
- Xcode 命令行工具（`swiftc`）

模型国内下载慢时可用镜像，脚本默认就是优先走镜像：

```bash
HF_ENDPOINT=https://hf-mirror.com python3 scripts/fetch_models.py
```

## 规格与底色

| 规格 | 像素 | 打印尺寸 | 比例 |
|---|---|---|---|
| 学籍照 | 480×640 | — | 1.3333 |
| 一寸 | 295×413 | 25×35mm @300dpi | 1.4000 |
| 二寸 | 413×579 | 35×49mm @300dpi | 1.4019 |
| 护照/大二寸 | 390×567 | 33×48mm @300dpi | 1.4538 |

比例各不相同，但头部占比和边距都是**比例**，所以各规格的纵向裁切相同、只差宽度，
且都居中于人脸中线 —— 因此可以在**最宽的裁切上只修一次图**，其余规格横向切片复用。
裁切框超出原图时用 alpha=0 补边，而非夹取，以保持比例严格正确。

构图：头部占画面高度 64%，头顶留白 9%。

**底色**（规格不统一，以受理机构要求为准）：

| 用途 | RGB |
|---|---|
| 白底 | `#FFFFFF` |
| 蓝底（标准天蓝） | `#438EDB` |
| 深蓝（考公，考试系统常用） | `#0066CC` |
| 红底 | `#FF0000` |

## 页面选项

- **底色** / **规格**：默认只勾「白底 + 一寸」，其余按需勾
- **文件大小**：不限 / ≤50KB / ≤100KB / ≤200KB。在上限内取最高画质（二分搜索
  JPEG 质量 40–98），只在实在放不下时才降色度抽样
- **抠图精度**：
  - 标准（快）— RMBG-1.4，约 9 秒
  - 高精度（慢）— BiRefNet，约 31 秒，细碎飞发保留完整得多
- **精修**：磨皮、美白、提亮眼下

## 命令行

服务之外也可以直接调库：

```python
from pathlib import Path
from idphoto import pipeline

results, warnings = pipeline.process(
    Path("photo.jpg").read_bytes(), Path("./work"),
    do_retouch=True, max_kb=100, matting_backend="birefnet",
)
```

`cli/` 下另有原始脚本（`make_id_photo.py`、`retouch.py`），参数比页面更全，适合精细调参。
`cli/ask_vision.py` 可以把图片发给本机 ollama 的视觉模型做质量评估。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 手机端页面 |
| GET | `/api/specs` | 规格 / 底色 / 体积 / 精度预设 |
| GET | `/api/health` | 探活 |
| POST | `/api/process` | 上传照片，返回全部结果 |
| GET | `/api/result/{job}/{file}` | 取结果图（1 小时后过期） |

`POST /api/process`：`photo`（文件）、`sizes`、`colors`（逗号分隔）、`retouch`、`max_kb`、`quality`。

处理是**串行**的（全局锁）。高精度档一次约 31 秒，两个请求同时到达时第二个会排队。

## 实现上值得一提的几点

这个项目踩过的坑比写过的代码多，主要几条（完整版见
`.claude/skills/id-photo-retouch/SKILL.md`）：

**抠图必须用模型，启发式修不了内部误判。** 最初用 Vision 语义分割 + 两色关系
`a=(C−B)/(F−B)` 做启发式修边。它在轮廓边界有效，但**实心区是不生效的**，所以当分割
把一块背景误判进轮廓内部时，下游没有任何环节能纠正它 —— 实测那张参考照片有 8.5 万
像素如此，最大一块 2.9 万像素。换学习型 matting 模型后直接消失。

**发丝细节靠分块推理。** 模型固定 1024 输入是细节天花板，1200 万像素压到 1024 后
几个像素宽的细发就没了，发际线会光滑得像假发套。切成带重叠的块分别推理再羽化融合
等价于分辨率翻倍。但**不是块数越多越好**：3×3 时每块里主体占比变小、偏离训练分布，
发际线反而发灰发糊。

**色度要按比例降，不能减固定值。** 美白原来对所有亮度都减 a\*−1.0、b\*−2.0，
但暗部（b\* 仅 5.8）等于被削掉三分之一黄度，眼睑、眉间、发际就发灰绿。改成按比例
缩放后暗部几乎不动。

**反解只在半透明处做。** `F=(C−B(1−a))/a` 除以 α 会放大色度差。蒙版在眼睛附近
α 会低于 1，那里被反解「去暖」就成了灰绿眼影。改成 α>0.95 处跳过反解。

**验收方法本身也有坑。** 成品是**裁切图**，拿整张原图缩到同一尺寸去比是错的取景；
量边缘清晰度时，原图背景是亮墙而成品是蓝底，对比度本就不同，指标会被背景变化污染。
这类问题我踩了不止一次 —— 结论是**边缘质量必须看图，数值指标只能当辅助**。

## 已知限制

- 仅 macOS
- 单张照片、单人正面；侧脸、多人、无脸会返回中文提示
- 去痣功能**故意没有做**：痣属于身份特征，抹掉会降低与学籍档案、身份证的比对一致性
- `vendor/models/` 占 1.1 GB。只想跑「标准」档的话可以删掉 `birefnet.onnx`
